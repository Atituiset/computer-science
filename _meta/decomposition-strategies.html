3. 分治 vs 贪心 vs DP: 什么是"最优子问题分解"

一句话

分治 / 贪心 / DP 表面上是三种范式, 仔细一看它们是"怎么把原问题分解成子问题的三个程度":从最不限 (分治) 到最严 (DP 表上每个子问题被重算维护). 理解三种范式的"分解自由度"梯度, 你面对新一道题能机械尝试.

分级: 从"分解自由度"看三种范式

分治: 任意分解 (递归从不考虑未来), 每子问题解一次
贪心: 每步只看眼前, 不回退, 不组合
DP:   列所有子问题, 顺序求解, 子问题之间共享解

三者都是"分解 + 合并", 但对分解形态的约束依次更紧:

  • 分治: 分形无要求, 子问题独立;
  • 贪心: 局部决策 == 全局决策, 即"无后效"+凸性"对最近的局部正确";
  • DP: 子问题之间存在重叠, 显式表达依赖以利 memo.

数学表达

考虑原问题 P(x). 三种范式中我们将 P 分解为子问题 P(x_i):

分治: P(x) = combine(P(x1), P(x2)). 子问题彼此独立.

贪心: P(x) = if condition x_k satisfiable, then choice(x_k) + P(rest). 选择完直接剪掉这一步.

DP: P(x) = opt_i P(x_i') + cost. 子问题之间是重叠 的, 即多个 P(x) 共享相同的 P(x_i') 子问题. 写一个表把所有子问题按顺序求解, 共享中间结果.

三种范式的共同源头

每种范式都假设最优子结构:

P(x*) 的最优解由 P(x_i) 的最优解组合而成。
若 subproblem-specific optimum is determined by "max/min", 
原则严格保持最优.

进一步:

  • 分治: 不要求定序, 只要组合函数保持一致;
  • 贪心: 多了"无后效"+ "组合函数有局部最优" 的"凸性"假定;
  • DP: 多了 "子问题可枚举集合 P(x_i) 有限" 的"有限制" 假定.

记忆: 更紧的假设 对应更复杂的录入, 但也允许更紧的复杂度上界.

同一道题三种范式的不同

例子: Longest Increasing Subsequence (LIS).

分治解: NOT 适用

LIS 并不太可分治, 因为子问题之间无可独立合并. 写成分治需要额外"在合并阶段 cross-processing"复杂度反而 O(n log² n) 或更高.

DP 解: 经典 O(n²)

dp[i] = max(dp[j] + 1) for j < i, a[j] < a[i]

dp[i] 依赖所有 dp[j] (j < i). 子问题重叠明显, 直接 DP 表.

贪心 + 二分: O(n log n)

观察: 不需要保留所有 dp. 仅需 tails[k] = 长度为 k+1 的 LIS 末尾最小值. 当一个新元素进来时, 比 tails[k] 大则附加, 否则替换 tails 中第一个比它的 (binary search 替换).

这是一个 "DP + 结构 + 贪心化简" 的形式：DP 的全表达不是必需, 可以用多余信息做剪枝退化为贪心.

工程师视角: 选择哪种范式

1. 看子问题之间是否有独立的"非线性表" 形态？
   有 → 分治.
2. 看是否 "局部最优即全局最优" 有凸性保证？
   有 → 贪心.
3. 子问题重叠？
   是 → DP.
4. 用 DP 但发现某维可被代数压缩？
   是 → 简化到"DP+贪心" 或"昭 ham".

多语言同构

DP 在所有语言里写法差不多. 但工程上记忆化 vs 显式表给语言选用带来差异:

语言记忆化写法显式表写法
Python@cache 一行dp[k] 显式迭代
TS闭包 + memo Mapdp[]: number[] 迭代
Gomap[state]int一层循环 dp
C++vector<int> memo + 递归dp[...] 一维数组滚动

@cache Python 是最优雅的入口 (一行装饰器即可), 但在大 input 上 Python 递归栈是 1000 限制障碍, 仍需"拓扑序迭代". 工程上惯用模式:

from functools import lru_cache
@lru_cache(None)
def solve(i, j): ...
solve(0, n-1)

但重度规模必须改写为 dp[i][j] 循环迭代, 因为 Python 递归太慢、太深、栈可能爆.

工程现实

DP 类问题在大规模工程里特别少, 真实使用场景:

  • 序列对齐 (生物信息学);
  • Viterbi 译码 (通信、语音);
  • 强化学习 value iteration、Q iteration;
  • 矩阵链乘编译 (LAPACK、cuBLAS) ;
  • 路径规划: DP 加 A* 或 Dijkstra.

DP 不会作为日常产品代码反复出现, 但在工程某些"模型核心"位置上反复出: 你写的机器人控制, 序列对齐, 隐马尔可夫, 都先落到 DP 上.

这一章带走的东西

  • 分治 / 贪心 / DP 是"分解自由度" 严格递减范式的同一族;
  • 同一道题三种范式不一定都解, 但存在各范式的"退化路径";
  • DP 是最适合工程大模型核心的"子问题显式表达框架";
  • 各语言运行时给出的 syntactical 表达差异很大, 但抽象同构;
  • LIS 尾部二分 = "DP 解后用结构剪枝退化为贪心" 的经典模式.
